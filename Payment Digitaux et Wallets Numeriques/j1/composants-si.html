Composants SI

Définition

Vue composants SI (métier monétique)

Ensemble des briques applicatives et techniques qui portent les fonctions monétiques d’acceptation, d’acquisition, d’émission et de post-transaction (clearing / settlement), telles qu’elles apparaissent dans le SI des acteurs.

Détail

Rôle de chaque brique

  • POS / mPOS — capture de l’opération, interaction moyen de paiement, envoi vers la chaîne d’acquisition
  • Payment gateway — interfaces (API / protocoles), routage, contrôles de forme, journalisation ; souvent porte d’entrée marchand / canal digital
  • Acquiring system — traitement côté acquéreur / PSP : opérations marchandes, routage réseau, lien clearing
  • Issuing system — host d’autorisation, SI porteur : décision, plafonds, opposition, lien fraude / AuthN selon organisation
  • Clearing & settlement — compensation puis règlement des positions (souvent différé, via scheme / mécanismes interbancaires)

Correspondance

Chaîne de valeur ↔ composants

Terminal

POS / mPOS (+ souvent payment gateway)

Acquéreur

Acquiring system (+ gateway / PSP selon le montage)

Émetteur

Issuing system (centre d’autorisation / host)

Post-transaction

Clearing & settlement

Message formateur

Une même banque peut opérer plusieurs composants (émettrice et acquéreuse). Le scheme reste externe, mais le SI s’interface avec lui.

Ancrage

Cas pratiques

Cas 1 — Banque émettrice

  • Chez elle : issuing (+ évent. AuthN / ACS)
  • Hors SI : POS marchand, acquiring tiers
  • Faire lister « ce qui est à nous »

Cas 2 — Banque acquéreuse / PSP

  • Cœur : gateway + acquiring
  • Issuing chez d’autres établissements
  • Clearing / settlement via scheme / partenaires

Cas 3 — Parcours e-commerce

  • Où est la gateway ?
  • Où commence l’acquiring ?
  • Où l’issuing décide ?

Cas 4 — Timeout d’autorisation

  • Quel composant suspecter en premier ?
  • Gateway · acquiring · réseau · issuing
  • Renvoi blocs Autorisation / online-offline

Pièges

Frontières à ne pas brouiller

  • Gateway ≠ toujours acquiring (souvent distincts)
  • Clearing ≠ settlement
  • Le « SI monétique » n’est rarement qu’un seul monolithe — parler par fonctions
  • Ne pas empiler ici fraude, tokenisation, wallet manager → J3 / J4 / J5
Notes formateur — questions SI
  • Chez vous, quels composants sont internalisés vs externalisés (PSP, scheme, processeur) ?
  • La gateway est-elle un produit séparé ou intégrée à l’acquiring ?
  • Qui opère réellement clearing et settlement dans votre organisation ?

Check de fin de bloc

  • Les 5 composants cités avec leur rôle
  • Distinction acceptation / processing / post-transaction
  • Au moins un cas « chez nous » placé sur la carte
  • Conscience que J5 enrichira sans surcharger J1
Sources normes / specs — à affiner : documents d’architecture de référence scheme / processeurs, périmètre PCI DSS par type de composant, interfaces messages d’autorisation.
