1.4 · Flux transactionnel

Settlement

Définition monétique

Qu’est-ce que le settlement ?

Processus par lequel les positions établies lors du clearing sont réglées entre les parties (comptes de règlement, agents de règlement, mécanismes scheme / interbancaires), de sorte que les obligations financières correspondantes sont éteintes.

Après le clearing : on exécute le règlement des positions.

Chaîne post-transaction

Où se situe le settlement ?

Trois temps distincts — le settlement est l’étape mise en évidence.

Autorisation → Clearing → Settlement

Simplifié · étape 3 = ce bloc

Modes monétiques

Net settlement · Gross / RTGS

Selon le rail, on règle des soldes nets après compensation, ou chaque obligation en brut (souvent RTGS).

Net settlement

Positions nettes issues du clearing → un règlement par cycle

Gross / RTGS

Règlement brut, souvent en temps réel — moins de netting

Cartes retail : souvent net après chambre. Gros montants / urgents : plutôt RTGS.

Règlement

Des positions au soldé

Le settlement ne « paie » pas le commerçant directement : il éteint les positions entre établissements. Le crédit marchand suit le contrat acquéreur / PSP.

Chaîne de settlement

Positions · Instructions · Comptes · Soldé

Cut-offs, jours ouvrés, liquidité : incidents propres au settlement — distincts d’un decline d’autorisation.

Mécanisme de règlement

Que se passe-t-il concrètement ?

Le mécanisme (ex. TARGET, agent scheme) ne « crédite » pas le commerçant : il exécute les instructions sur les comptes de règlement.

Dans le règlement

Cut-off → comptes → soldé · ex. TARGET après CORE

Cas domestique

Même communauté — règlement via banque centrale / CSM local

Cas international

Frontière / scheme — règlement selon règles Visa / Mastercard…

Une carte internationale peut clear / settle via scheme alors que le clearing STET + TARGET reste le cas domestique euro.

Repères mondiaux

Mécanismes de règlement connus

Exemples pédagogiques — RTGS, agents scheme, rails associés au clearing du tableau précédent.

Rôle

Que fait le settlement ?

Exécution

  • Règle les positions issues du clearing
  • Net : soldes après compensation
  • Gross / RTGS : obligations unitaires

Infrastructure

  • Comptes BC / agents, cut-offs
  • Europe : TARGET après chambre (STET…)
  • International : mécanismes Visa / Mastercard…

Soldé (« qui a payé qui »)

  • Obligations interbancaires éteintes
  • Pas encore le crédit marchand « vécu » (contrat acquéreur)
  • Incidents = liquidité / calendrier — ≠ decline d’auth

Ancrage

Cas pratiques

Cas 1 — Fil rouge J1

  • Autorisation OK → clearing OK → settlement
  • Puis crédit marchand selon contrat
  • Reposer toute la chronologie

Cas 2 — Settlement en retard

  • Positions clearing connues
  • Règlement non abouti (cut-off, incident…)
  • ≠ decline d’autorisation

Cas 3 — Écart de réconciliation

  • Montant autorisé ≠ présenté clearing ≠ réglé / crédité
  • Placer l’écart sur la chaîne

Clarification

Ce que le settlement n’est pas

≠ Autorisation OK

Le OK émetteur n’est pas un virement définitif vers le commerçant.

≠ Clearing

Le clearing calcule / compense ; le settlement règle les soldes qui en résultent.

≠ Crédit marchand « vécu »

Le moment où le commerçant voit les fonds dépend du contrat acquéreur / PSP — lié au settlement, mais pas identique.
