1.3 · Architecture générale

Chaîne de valeur

Définition monétique

Qu’est-ce que la chaîne de valeur ?

Séquence ordonnée des maillons que traverse une opération — de l’initiation côté acceptation jusqu’à la décision côté émetteur, puis le chemin de retour de la réponse.

Ce bloc répond à une seule question : dans quel ordre ? — pas qui (acteurs), pas dans quels SI (composants).

Client → Terminal → Acquéreur → Réseau → Émetteur

Deux lectures

Message · Argent

Même acteurs en fond, deux parcours à ne pas fusionner.

Vue message (ce bloc)

  • Demande d’autorisation → décision → réponse
  • Temps réel / quasi temps réel
  • Prépare le bloc Autorisation

Vue argent (plus tard)

  • Clearing → settlement → crédit marchand
  • Après coup, calendriers / cut-offs
  • Blocs Clearing & Settlement

Deux temps sur la même opération

Ne pas s’arrêter mentalement au « OK » émetteur

Schéma

Aller et retour

Cliquez un maillon. Sans le retour de réponse, pas d’expérience d’acceptation complète.

Client → … → Émetteur

Demande d’autorisation · réponse approve / decline

Parcours du message

Cliquez un maillon. En modèle carte classique, le PAN circule dans cette chaîne — pont vers la tokenisation (J3).

Maillons

Ce qui circule à chaque étape

À chaque hop : une action monétique distincte — pas seulement un nom d’acteur.

Variantes

Trois montages PSP / acquéreur

Même ordre logique. Ce qui change : le PSP est-il absent, devant l’acquéreur, ou l’acquéreur lui-même ?

Anti-confusion

PSP ≠ toujours distinct de l’acquéreur — regarder le contrat et le statut scheme.

1 · Banque acquéreuse classique

Pas de PSP nommé — l’acquéreur porte le maillon

Exemple Commerçant de proximité contracté directement par sa banque (POS « maison ») — pas de marque PSP au milieu du parcours. Typique ; le contrat exact peut varier.

2 · PSP devant l’acquéreur

Deux boîtes — technique puis rôle scheme

Exemple Gateway / checkout d’un PSP technique qui route ensuite vers une banque acquéreuse partenaire. Deux entités visibles. Typique ; le contrat exact peut varier.

3 · PSP-acquéreur

Une seule boîte — double étiquette

Exemple Paybox (écosystème Verifone) — ou, selon pays / contrat, un Adyen / Stripe : le commerçant « voit » le PSP, qui porte aussi (souvent) le rôle d’acceptation face au scheme. Typique ; le contrat exact peut varier.

En salle : demander « chez vous, montage 1, 2 ou 3 ? » avant de tracer la chaîne.

E-commerce (rappel)

« Terminal » = checkout — puis l’un des 3 montages ci-dessus

Exemple Boutique en ligne : page de paiement Paybox (ou autre PSP) = maillon checkout, puis montage 2 ou 3 selon que le PSP s’appuie sur une banque acquéreuse ou porte lui-même le rôle.

Clarification

Ce que la chaîne n’est pas

≠ Acteurs

Les acteurs disent qui ; la chaîne dit dans quel ordre le message passe chez eux.

≠ Composants SI

Les composants disent dans quels systèmes ; un maillon peut s’appuyer sur plusieurs briques.

≠ Autorisation seule

La chaîne porte le message ; l’autorisation est la décision typique de l’émetteur sur ce message.

PSP ≠ toujours acquéreur

Trois montages possibles — ne jamais dessiner « PSP puis acquéreur » par défaut.

Ancrage

Cas pratiques

Cas 1 — Reconstituer l’ordre

  • 5 étiquettes, sans notes

Cas 2 — Quel montage PSP ?

  • Chez vous : 1, 2 ou 3 ?
  • Contrat + statut scheme

Cas 3 — E-commerce

  • Checkout = terminal
  • Puis appliquer le bon montage PSP / acquéreur

Cas 4 — Réponse absente

  • Enquêter maillon par maillon (horodatages)
Notes formateur
  • Faire redessiner la chaîne au tableau avant le schéma projeté
  • Insister sur le retour : beaucoup s’arrêtent mentalement à l’émetteur

Check de fin de bloc

  • Chaîne complète restituée dans l’ordre
  • Vue message ≠ vue argent
  • Les 3 montages PSP / acquéreur distingués
  • Sens demande / réponse compris
  • Transition claire vers composants SI
