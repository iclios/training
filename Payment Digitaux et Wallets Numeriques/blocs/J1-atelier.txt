================================================================================
1. MÉTA FORMATEUR
================================================================================
Objectif pédagogique
Ancrer le Jour 1 avec deux rails : (A) terminal Lane 5000 + cartes de test
(contact / sans contact) — init, transactions, télécollecte ; (B) Postman
approve / decline — lire les champs et les coller sur la chaîne.

Idée clé
« Le geste caisse et le message d’Auth disent la même histoire monétique —
surfaces différentes. »


================================================================================
2. MATÉRIEL
================================================================================
Physique
- Terminal Ingenico Lane 5000 (paramétrage TEST)
- Cartes de test contact + sans contact
- Tickets / journaux si disponibles

Logiciel
- Postman
- Fichiers atelier/j1-postman/ :
  · mock_auth_server.py (mock ISO 8583, port 8787)
  · J1-Auth-Approve-Decline.postman_collection.json
- Joindre les 2 fichiers au support étudiant (PDF / mail)

Usage Postman (ISO 8583 packé)
1. python3 mock_auth_server.py
2. Import du JSON (ou saisie manuelle)
3. Auth 0100→0110 : bitmap.hex + message_hex + DE38/DE39
4. Decline : DE39=51, DE38 absent du bitmap
5. Clearing/compensation 0220→0230 : DE38 + DE90 (lien Auth) + message_hex
Note : message_hex = MTI+bitmap+DE (lien host pédagogique). Fichiers scheme (IPM/Base II) évoqués en note.


================================================================================
3. RAIL A — LANE 5000
================================================================================
1. Initialisation — réseau, paramètres marchand (MID, TID), état terminal
2. Transactions — contact (puce/PIN) puis sans contact ; approve (+ decline si possible)
3. Lecture ticket — auth code, MID/TID, mode, statut → placer sur la chaîne
4. Télécollecte — remontée lots / journaux ; Auth ≠ TC ≠ Settlement

Scénarios optionnels (si config)
- Annulation / remboursement
- Seuil contactless (PIN / CDCVM)
- Échec réseau / offline
- Timeout / double présentation


================================================================================
4. RAIL B — POSTMAN
================================================================================
1. APPROVE — noter status, auth code, ids
2. DECLINE — code / motif · métier vs technique
3. Placement groupe — champ → émetteur / acquéreur / réseau / PSP / terminal
4. 3 phrases chrono — Auth → Clearing → Settlement

10–15' Débrief · teaser J2 QR
