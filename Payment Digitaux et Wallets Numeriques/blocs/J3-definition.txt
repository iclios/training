JOUR 3 — Définition

Objectif pédagogique
Définir la tokenisation, distinguer PAN / token / vault / TSP, et expliquer
comment on obtient le token (provisioning) — sans encore dérouler objectifs
ni domaines (fiches dédiées).

Contenu
- Définition monétique (substitution PAN → token, rail Auth inchangé)
- PAN vs token (+ visuels carte / wallet)
- Vault & TSP (en exergue)
  · Vault = coffre du mapping PAN ↔ token
  · TSP = qui émet / gouverne les états
  · Placement chaîne J1 : souvent côté réseau/scheme (pas chez le marchand) ;
    émetteur garde PAN + AuthZ — détail Architecture SI
- Comment on obtient le token (demande → contrôles → émission → remise)
- UX wallet : schéma enrolment implicite (TSP réseau ≠ CB2A Auth)
- Clarification :
  · PAN tronqué = stockage d’un fragment (PAN non reconstitutable)
  · PAN masqué = affichage flouté (PAN complet peut encore exister)
  · Token = autre identifiant gouverné
  · ≠ chiffrement · ≠ nouveau rail · ≠ risque zéro
