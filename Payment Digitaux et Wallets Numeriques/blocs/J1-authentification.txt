BLOC — FORMATEUR
Cours : Paiements digitaux & Wallets numériques
Jour 1 · Flux transactionnel carte
Bloc : Authentification
Durée indicative : 20–30 min
Précédent : Autorisation · Suivant : Clearing
Sources normes : à affiner (EMV, 3-D Secure / EMV 3DS, SCA / DSP2…)


================================================================================
1. MÉTA FORMATEUR
================================================================================
Objectif pédagogique
À la fin du bloc, les participants définissent l’authentification au sens
monétique, la localisent dans le cycle EMV (CVM · étape 4), la distinguent
de l’autorisation, et illustrent proximité vs e-commerce.

Idée clé
« Authentification = légitimité du porteur / device / parcours.
Autorisation = accord de l’émetteur sur l’opération. »

Posture
1) Définition monétique
2) Localiser AuthN dans le cycle EMV (étape 4 · CVM)
3) Quatre canaux → modes AuthN → convergence autorisation
4) Ancrage : trois cas de mode (POS · checkout · wallet)


================================================================================
2. DÉFINITION MONÉTIQUE
================================================================================
Authentification (paiement par carte / monétique)
Ensemble des procédures permettant de s’assurer, avec un niveau de confiance
adapté au canal, que l’opération est initiée par le porteur légitime du
moyen de paiement — ou via un dispositif / parcours reconnu comme tel.


================================================================================
3. PLACE DANS LE CYCLE DE VIE EMV
================================================================================
Schéma illustré — localiser l’étape 4 (ce bloc)
1. Sélection d’application
2. Lecture des données
3. Authentification des données (offline)
4. Vérification du porteur (CVM · AuthN) ← CE BLOC
5. Analyse de risque
6. Autorisation online (AuthZ)
7. Fin de transaction

Contraste utile : AuthN (étape 4) ≠ autorisation (étape 6).


================================================================================
4. CANAUX → MODES AUTHN → CONVERGENCE
================================================================================
1) Carte (POS) — CVM : PIN · signature · seuils sans contact
2) Web (checkout) — 3-D Secure : challenge / frictionless · ACS
3) Wallet (tap) — biométrie device / CDCVM (détail J4)
4) In-app — 3DS / SDK / wallet embarqué selon intégration

Tous convergent vers l’autorisation émetteur (accord / refus).
Le canal change le mode AuthN — pas le décideur.


================================================================================
5. CAS — TROIS MODES
================================================================================
Cas 1 — POS magasin → CVM (PIN / seuils)
Cas 2 — Checkout web → 3DS (challenge / frictionless · ACS)
Cas 3 — Tap wallet → CDCVM / biométrie device
Oral — In-app : selon intégration (3DS / SDK / wallet)
