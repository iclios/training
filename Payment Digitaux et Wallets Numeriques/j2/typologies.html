Principes & typologies QR

Définition

Qu’est-ce qu’un QR code ?

QR = Quick Response (« réponse rapide ») — code-barres 2D inventé pour être lu vite, même abîmé ou sous angle. Il encode une chaîne de données : texte libre, URL, contact, identifiant technique, ticket, configuration… — pas uniquement un paiement.

Payload

Le payload est la charge utile portée par le QR : les octets / caractères que le lecteur récupère après scan. Le QR n’est que le support optique ; le payload, c’est le contenu — n’importe quelle chaîne comprise par l’app qui lit.

Support optique

Génération du QR

Le payload est le contenu. L’algo de génération (norme ISO/IEC 18004) le transforme en matrice de modules noir / blanc — en pratique une librairie, pas un moteur maison.

Pipeline de génération

De la chaîne de caractères à l’image scannée

Cas d’usage

Du support au paiement

  • Même support optique — toujours un QR (ISO/IEC 18004)
  • Payload paiement — compris par une app (banque / wallet / marchand)
  • Action — initier ou recevoir une opération
  • Plusieurs axes — changent le SI et le risque (pas « un seul objet »)

Payload de paiement — exemple

Format pédagogique (pipe) · équivalent simplifié d’un QR statique 

PAY|MID:TRAIN|AMT:|CUR:XOF|REF:STAT|POI:11
PAY Objet

Indique un QR de paiement (pas un lien web générique).

MID:TRAIN Marchand

Identifiant commerçant / compte à créditer.

AMT: Montant

Vide → le payeur saisit après scan (typique du statique).

CUR:XOF Devise

Code monétaire (ici franc CFA).

REF:STAT Référence

Libellé / référence métier côté acceptation.

POI:11 Mode d’initiation

11 = statique (convention type EMV) ; 12 = dynamique.

En production, le même rôle est souvent porté par un payload TLV (ex. EMV QR) : mêmes idées (IDs, montant, devise, CRC…), autre syntaxe.

Quatre axes à maîtriser — chaque couple change ce payload et le SI autour.

Modes monétiques

Statique vs dynamique

  • Statique — contenu fixe (souvent ID marchand)
  • Dynamique — payload généré pour une opération (montant, réf., TTL)
  • EMV QR — tag 01 = 11 (statique) / 12 (dynamique)
  • Statique — le QR dit qui créditer ; le combien (et souvent la réf.) vient après le scan
  • Dynamique — le QR dit qui + combien + réf. (+ TTL) ; généré pour cette opération, puis jeté / expiré

Statique · Dynamique

Qui porte le montant — EMV tag 01 · 11 / 12

Sortez le téléphone — scannez les deux. À gauche le payload ne change jamais ; à droite il expire et se régénère.

Modes monétiques

              
Bancaire vs wallet

              

                Ce n’est pas deux types de QR. C’est le
                chemin après le scan : rails bancaires directs, ou
                passage par une orchestration wallet.
              


              

                
Wallet ≠ app

                

                  Le wallet est un moyen d’orchestration
                  (choisir l’instrument, authentifier le porteur, présenter
                  le credential…). L’app est la façade qui
                  appelle le wallet — pas le wallet lui-même.
                  Détail stack au Jour 4.
                

              


              

                
« QR wallet » — pas un vocabulaire EMV

                

                  EMVCo ne définit pas « QR bancaire » /
                  « QR wallet ». Il parle de
                  MPM / CPM, de
                  mobile application (banque émetteur ou tiers) et
                  parfois de mobile application/wallet ou
                  Issuer / third-party wallet — sans en faire un
                  type de payload. Sur le terrain, « wallet QR »
                  désigne souvent un rail e-wallet (vs
                  règlement compte bancaire) ou un jargon produit — pas une
                  classe optique du QR.
                

              


              
    
                
  • 
                  Souvent le même QR — sticker / ticket
                  marchand interop (EMV, QR national)
                
    • 
                
  • 
                  Bancaire — l’app (souvent banque) enchaîne
                  vers les rails banque / PSP, sans couche wallet
                
    • 
                
  • 
                  Via wallet — l’app appelle le wallet, qui
                  orchestre le paiement (multi-moyens, solde, token…)
                
    • 
                
  • 
                  Exception — QR propriétaire closed-loop :
                  payload compris seulement dans cet écosystème wallet
                
    • 
                
  • 
                  Ici (J2) — distinguer le
                  chemin ; pas encore token / SE / NFC
