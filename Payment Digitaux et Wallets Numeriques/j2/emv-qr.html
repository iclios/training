Focus EMV QR

Définition

Qu’est-ce que la spec EMV QR ?

Les EMV QR Code Specifications (EMVCo) définissent le format du payload d’un QR de paiement (TLV, IDs, CRC, MPM / CPM…) — ce que la chaîne contient pour initier une transaction. Ce n’est pas l’encodage / décodage optique du symbole (ISO/IEC 18004), ni le protocole réseau après le scan (Auth / clearing), ni les specs EMV carte à puce.

  • Deux documents — MPM (marchand présente) et CPM (consommateur présente)
  • But — un format commun pour qu’apps et réseaux lisent le même type de payload
  • Limite — messaging après lecture = hors scope (scheme, issuer, PSP)

Parallèle avec EMV chip

Couche support (ISO) · couche paiement (EMVCo)

À retenir

18004 = processus de génération (et de décodage) du symbole : modes, version, correction d’erreur, masque… EMV QR = ce que la chaîne de données paiement contient avant / après ce passage. Pour le sans-contact carte, le parallèle radio est plutôt ISO 14443 → EMV Contactless.

    Deux specs

    MPM · CPM

    Critère unique : qui présente le QR (déjà vu en Typologies).

    MPM

    • Merchant-Presented Mode
    • Marchand affiche · payeur scanne
    • Payload = infos marchand (± montant)
    • Cas courant : sticker, ticket, caisse

    CPM

    • Consumer-Presented Mode
    • Payeur affiche · caisse / terminal scanne
    • Payload = credentials côté consommateur
    • Souvent lié à un instrument provisionné
    Mode Tag format Valeur Rôle
    MPM 00 01 Payload se parse en TLV MPM
    CPM 85 CPV01 Payload se parse en BER-TLV CPM

    Le format dit quelle grammaire lire — pas le profil national ni le moyen. Une seule valeur définie par spec aujourd’hui. Suite du cours = surtout MPM ; CPM = même famille, autre sens.

    Syntaxe

    TLV — Tag · Length · Value

    Au tableau : chaque objet du payload EMV QR est un triplet. On lit de gauche à droite, objet après objet, jusqu’au CRC.

    Un objet = trois cases

    Type (ID) · Taille · Valeur — toujours dans cet ordre

    L’app lit 000201, vérifie le format 01, puis avance de 2 + 2 + L jusqu’à 63 (CRC). Suite : un payload complet.

    Format CPV01 · Application Template · Common Data

    Pourquoi pas une chaîne type MPM ? MPM = TLV texte (chiffres / ASCII) directement dans le QR. CPM = BER-TLV binaire → la spec impose un encodage Base64 dans le symbole (ce que lit le scanneur en texte).
