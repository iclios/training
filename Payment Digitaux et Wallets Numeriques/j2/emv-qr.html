Focus EMV QR

Définition

Qu’est-ce que la spec EMV QR ?

Les EMV QR Code Specifications (EMVCo) définissent le format de données d’un QR de paiement : comment encoder / décoder le payload pour initier une transaction. Ce n’est pas le protocole réseau après le scan (Auth / clearing), ni la norme optique ISO/IEC 18004, ni les specs EMV carte à puce.

  • Deux documents — MPM (marchand présente) et CPM (consommateur présente)
  • But — un format commun pour qu’apps et réseaux lisent le même type de payload
  • Limite — messaging après lecture = hors scope (scheme, issuer, PSP)

Parallèle avec EMV chip

Couche support (ISO) · couche paiement (EMVCo)

À retenir

18004 = processus de génération (et de décodage) du symbole : modes, version, correction d’erreur, masque… EMV QR = ce que la chaîne de données paiement contient avant / après ce passage. En sans contact carte, le parallèle radio est plutôt ISO 14443 → EMV Contactless.

    Deux specs

    MPM · CPM

    Critère unique : qui présente le QR (déjà vu en Typologies).

    MPM

    • Merchant-Presented Mode
    • Marchand affiche · payeur scanne
    • Payload = infos marchand (± montant)
    • Cas courant : sticker, ticket, caisse

    CPM

    • Consumer-Presented Mode
    • Payeur affiche · caisse / POI scanne
    • Payload = credentials côté consommateur
    • Souvent lié à un instrument provisionné

    Suite du cours = surtout MPM (acceptation marchand). CPM = même famille, autre sens du flux optique.

    Syntaxe

    TLV — Tag · Length · Value

    Au tableau : chaque objet du payload EMV QR est un triplet. On lit de gauche à droite, objet après objet, jusqu’au CRC.

    Un objet = trois cases

    Type (ID) · Taille · Valeur — toujours dans cet ordre

    L’app avance de 2 + 2 + L caractères, puis recommence — jusqu’à l’objet 63 (CRC). Suite : un payload complet.

    Règles utiles

    Cinq points opérationnels

    Côté génération

    • Ordre des IDs et CRC calculé sur le payload
    • Statique : pas (ou peu) de montant
    • Dynamique : montant + réf. + fenêtre de vie

    Côté lecture

    • Parser TLV → valider CRC → extraire IDs
    • Caméra OS seule ≠ app paiement
    • Messaging Auth = hors scope EMV QR (réseau / issuer)
    • Un QR, plusieurs programmes — plusieurs blocs Merchant Account possibles dans le même sticker (selon marchés)
    • Account-based et card-based — EMV QR peut porter les deux familles (champs prévus)
    • RFU — IDs réservés : l’app doit ignorer ce qu’elle ne connaît pas (évolutivité)
