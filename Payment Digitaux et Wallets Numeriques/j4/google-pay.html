4.3 · Wallet majeur

Google Pay

Définition

Qu’est-ce que Google Pay ?

Wallet Android qui orchestre enrolment, token, CDCVM et présentation — souvent HCE + TEE — sans remplacer l’émetteur ni l’AuthZ.

Point Google Pay
Stack HCE + TEE (déjà vu Architecture wallets)
Trois canaux proximité (NFC) · in-app · e-commerce
TSP Vault TOKEN↔PAN · détokenisation Auth · coffre UDK-AC + recharge HCE — pas Google

Apple Pay · J3 lifecycle

Plateforme

Écosystème Android

Multi-OEM, multi-versions OS — lire le device, pas « un » Android unique.

OS · fragmentation · NFC

Vue d’ensemble — tout visible

1 · OS

Android · Wear OS · APIs

Google Pay / Wallet · Play Services / attestation device souvent dans la boucle de confiance.

In-app / web : Google Pay API — parallèle PassKit, autre intégration SI.

Docs issuer Google Pay + contraintes Android par OEM.

2 · Parc

OEM · versions · fragmentation

Constructeurs multiples · NFC · qualité TEE / SE variable.

Un même « Google Pay » ≠ même profondeur de sécurité hardware. Wear = domaines token possibles.

Ne pas enseigner « un » schéma unique pour tout Android.

3 · NFC / HCE

Card emulation host

Émulation côté host OS — le POS voit un flux contactless EMV. Sortie = token + crypto (pas le PAN).

Certains devices ajoutent un SE — exception, pas la norme pédagogique de base.

HCE ≠ absence de sécurité — TEE + recharge TSP.

Écosystème

Tous les acteurs monétiques

Même chaîne que Apple Pay — rôles monétiques identiques, stack device différente — vue d’ensemble.

Chaîne complète Google Pay

Porteur → Wallet → TSP → Issuer · POS → Acquéreur → Auth

Porteur

CDCVM · geste

Ajoute la carte, IDV issuer, authentifie (empreinte / visage / PIN). Compte Google = multi-devices possibles.

UX Android / Wear — biométrie selon constructeur.

Google Wallet

HCE · TEE · orchestre

UX, HCE, liaison TSP, présentation NFC / in-app. ≠ banque · ≠ TSP · ≠ AuthZ.

LUK / TTL via recharge TSP — pas le vault Google.

TSP / scheme

VTS · MDES · vault + coffre

Même rôle qu’Apple : token, vault, domaine, Auth. En HCE : coffre UDK-AC + recharge credentials courts.

Le réseau = cœur du mapping — pas le wallet Google.

Issuer

PAN · AuthZ · décide

OK provisioning · AuthZ · opposition. Multi-devices Android (re-provision, revoke).

Score risque / exigences device peuvent différer d’Apple.

POS

NFC EMV · voit TOKEN

Identique fonctionnellement à Apple Pay au tap. Le TPE ne distingue pas HCE vs SE dans le geste métier.

Différence = côté device, pas caisse.

Acquéreur / PSP

Auth TOKEN

Network tokenization → TOKEN jusqu’à l’acquéreur. In-app Google Pay = parallèle Apple in-app.

Même lecture token qu’Apple Pay NFC.

Provisioning ↑ · Paiement NFC → POS · acquéreur · réseau détokenise · issuer — même cartographie qu’Apple

Confiance device

Spécifique Google · rôle du TSP

Bases HCE / TEE : Architecture wallets. Ici = le TSP jusqu’à l’autorisation.

Composant Rôle
HCE Répond au POS (token + crypto) — pas d’UDK-AC durable locale
TEE Souvent TrustZone · CDCVM / protection
Google Wallet UX / API · orchestre · pas le vault TSP
TSP Coffre UDK-AC + vault TOKEN↔PAN + recharge credentials courts (TTL / stock de taps · envoi à l’enrolment puis quand le phone est online) + détokenisation Auth

TSP · du coffre au AuthZ

Plus qu’un mapping token — présent avant et pendant le paiement

Enrolment

Workflow · ajouter une carte

Même composants : demande au TSP · Issuer répond au TSP · TSP provisionne le téléphone (credentials courts vers HCE · UDK-AC reste au coffre TSP).

Use case : ajouter sa CB dans Google Wallet pour pouvoir payer ensuite (tap, in-app, web).

Canal 2 · In-app

Workflow Google Pay · in-app

Pas de RF : API Google Pay dans l’app · CDCVM → payload TOKEN → Auth via TSP (parallèle PassKit).

Use case : payer un trajet Uber / une commande Deliveroo dans l’app — bouton Google Pay.

Canal 3 · E-commerce

Workflow Google Pay · e-commerce

Site ouvert dans Chrome Android : le bouton Google Pay n’appelle pas un wallet distant — le navigateur déclenche la feuille Google Pay native du téléphone (même wallet / CDCVM / token que l’in-app) · Auth via TSP.

Use case : checkout web sur le téléphone (Zara, Fnac… dans Chrome Android). Sur PC, pas d’accès direct au wallet Android — d’où le focus mobile ici.
