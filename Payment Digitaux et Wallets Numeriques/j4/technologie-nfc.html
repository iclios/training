4.1 · Technologie NFC

Technologie NFC

Définition

Qu’est-ce que le NFC ?

NFC (Near Field Communication) : communication radio à très courte distance (centimètres), bidirectionnelle, pensée pour des interactions de proximité (« tap »). En paiement, c’est le canal physique entre le support (carte / mobile) et le terminal — distinct du QR (canal optique) et distinct de la tokenisation (identifiant présenté).

Principes physiques

Caractéristiques physiques essentielles

Distance courte, induction, antenne — le geste « tap » n’est pas cosmétique.

ISO/IEC 14443

Type A / Type B

Temps 1

Une norme, deux déclinaisons

ISO/IEC 14443 = la norme du sans contact de proximité (13,56 MHz, carte ↔ lecteur). Elle se décline en deux types : A et B.

Temps 1 · La norme se divise

14443 → Type A · Type B

Temps 2

Ce qui différencie A et B

Différence radio seulement — pas Visa vs Mastercard.

Le lecteur module le champ 13,56 MHz : A = fort, B = léger.

ASK (Amplitude Shift Keying) : modulation par variation d’amplitude du champ radio.

Temps 2 · Comment le signal est modulé

Lecteur → carte · même fréquence, deux enveloppes

En résumé A = radio « tranchée » (lisible, mais coupures) · B = radio « continue » (stable en énergie, mais signal plus fin) — ni A ni B interopérables entre eux
  • Carte / wallet paiement : Type A quasi exclusif.
  • POS certifié contactless : A et B (interop 14443) — filet pour les cartes B rares, pas le chemin courant.
  • Match : carte A ↔ POS A · carte B ↔ POS B.

Empilement

Où se placent A et B dans les couches

Type A / Type B = choix en bas (radio). Au-dessus, APDU et EMV sont les mêmes — quel que soit le type.

Couches · du bas (RF) vers le haut (paiement)

ISO 14443 = couche radio · A / B = fourche dedans

Choix marché

Pourquoi le paiement a choisi Type A

Type A · chemin dominant du paiement

Masse critique → standard de fait

Pour le tap carte / wallet au POS, on raisonne Type A. Le POS gère aussi B pour l’interop 14443 (carte B rare), pas parce que B est le chemin principal du paiement.

Interop radio

Quand l’un est A et l’autre B

A et B ne se comprennent pas au niveau radio. Il faut le même type des deux côtés (carte / wallet ↔ POS), sinon le tap échoue avant même l’EMV.

Carte / wallet × POS · même type ou échec

Quatre cas · une seule règle

Modes NFC

Trois modes à connaître

Un chipset, trois usages — seul le mode card emulation porte le paiement wallet.

Card emulation · Reader/writer · P2P

Rôles du device NFC

Mode 1

Reader / writer

Le téléphone est actif : il génère le champ et lit / écrit un tag passif. Pas de paiement.

Reader / writer · schéma

Téléphone = lecteur · tag = cible

Mode 2

Peer-to-peer

Deux devices s’échangent des données. Hors parcours carte / wallet au POS.

Peer-to-peer · schéma

Device ↔ device

Mode 3 · central J4

Card emulation · déroulement

Face au POS, le déroulement est le même qu’une carte sans contact (champ → Type A → APDU EMV CL → AuthZ). Ce qui change = le card emulation : le téléphone joue le rôle de la carte (SE / HCE + token), le POS ne voit pas un « app ».

Card emulation · schéma de rôles

POS = actif · téléphone = passif (comme une carte)

Card emulation vs carte sans contact

Même enchaînement POS · seuls support et données changent

À retenir · card emulation

  • Enchaînement POS = identique à la carte sans contact.
  • Différence = qui joue la carte (SE / HCE) et quoi dans les APDU (token, pas PAN).
  • Reader/writer et P2P ne portent pas le paiement wallet.

Normes

NFC Forum vs ISO 14443

Deux acteurs différents : ISO/IEC 14443 = tuyau radio carte ↔ lecteur · NFC Forum = comment un device NFC (téléphone, tag…) utilise ce tuyau et interopère. Le Forum n’est pas la spec monétique.

Ce que fait le NFC Forum

Consortium · specs device / tags / données — sur socle ISO

Ce que le NFC Forum spécifie

  • Modes · Digital Protocol (NFC-A/B/F/V) · Activity / Profiles
  • Tags · NDEF / RTD · LLCP / SNEP (P2P)
  • Device Requirements · Analog · Connection Handover

Ce que le NFC Forum ne fait pas

  • Pas de logique paiement : pas de CVM, seuils, cryptogrammes EMV, AuthZ, tokenisation.
  • Ça, c’est EMVCo (EMV Contactless) + schemes + TSP (J3) — pas le Forum.

Card emulation : le téléphone « ressemble » à une carte face à un POS déjà calé sur 14443 + EMV — le terminal n’a pas besoin de connaître tout le catalogue Forum pour accepter le tap.
