1.4

Flux transactionnel carte

Quatre phases à ne pas confondre — surtout en comité SI ou en incident production.

Phase 1

Autorisation

L’émetteur dit oui ou non : fonds / plafond / contrôles fraude. Réponse quasi temps réel.

Phase 2

Authentification

Preuve que c’est le bon porteur : PIN, 3-D Secure, biométrie (selon canal).

Phase 3

Clearing

Échange des opérations entre acquisiteur et émetteur via le réseau — compensation.

Phase 4

Settlement

Règlement effectif des positions : l’argent bouge entre institutions.

Séquence simplifiée

Online vs offline · latence · rejets

  • Online vs offline : offline = décision locale / différée, risque porté autrement
  • Rejets : lire le code (fonds, fraude, technique) — exercice de l’atelier
  • Pont J3 : ici le PAN circule ; demain le token le remplacera sans casser ce même schéma

Proposition pratique

Atelier palpable — suivre une transaction

Objectif : toucher une autorisation réelle (sandbox) et la replacer sur la chaîne de valeur.

Physique

  • 1 carte contact + 1 carte sans contact
  • Ticket de caisse ou capture ticket marchand

Logiciel

  • Sandbox PSP (Stripe / Adyen / Checkout)
  • Collection Postman : auth approve / decline

Déroulé (~45–60 min)

  • Payer en mode test
  • Lire auth code / decline reason
  • Placer chaque info sur le schéma émetteur / acquéreur / réseau / PSP

Règle salle : cartes et données de test uniquement — jamais de production.
