Jour 5 · Omnicanal

5.2 · Plateforme

Architecture d’une plateforme de paiement

Définition monétique

Qu’est-ce qu’une plateforme de paiement digitale ?

Ensemble de composants SI qui orchestrent l’acceptation multi-canaux, la tokenisation, les rails QR / NFC / wallet, le lien émetteur / acquéreur, la fraude, puis la réconciliation & settlement — avec un journal de vérité unique.

J1 = logique monétique · J2–J4 = rails · J5 = assemblage cible.

Vue d’ensemble

Schéma d’architecture cible

Gateway en façade ; cœur (wallet, token, QR, fraude) ; rails vers émetteur / acquéreur ; clôture financière.

Plateforme omnicanale

Canaux · Cœur SI · Rails · Clôture

Chaque brique = responsabilité SI claire (qui opère, qui certifie, qui supervise).

Flux

Un paiement traverse la plateforme

Exemple : wallet NFC in-store — du terminal au settlement.

Parcours type (wallet NFC)

Terminal → gateway → token → scheme → émetteur → journal

Rôle

Que fait chaque brique ?

Façade & confiance

  • Gateway : entrée, normalisation
  • Wallet manager : cycle de vie
  • Tokenization : PAN → token

Rails & clôture

  • QR engine · NFC / wallet
  • Liens émetteur / acquéreur
  • Réconciliation & settlement

Ancrage

Cas pratiques

Cas 1 — Brancher un nouveau canal

  • Nouveau front → même gateway
  • Pas de nouveau silo settlement

Cas 2 — TSP hors périmètre

  • Token chez scheme / TSP externe
  • Gateway reste le point d’orchestration

Clarification

Ce que ce n’est pas

≠ Un seul éditeur « magique »

La plateforme peut être assemblée (PSP + TSP + switch + banque).

≠ Remplacer Auth / Clearing / Settlement

Elle les orchestre — elle ne les invente pas.

≠ Architecture figée

Les frontières gateway / TSP / fraude varient selon le pays et le modèle opératoire.

Notes formateur — questions SI
  • Qui opère la gateway aujourd’hui chez vous ?
  • Le journal unique existe-t-il réellement, ou par canal ?
  • Où placez-vous le fraud engine (avant / après routing) ?

Check de fin de bloc

  • Briques gateway → cœur → rails → clôture situées
  • Liens émetteur / acquéreur rappelés
  • Synthèse J1–J4 visible sur le schéma
Sources normes / specs — à affiner : architectures référence PSP / switch nationaux, EMVCo, PCI, règles scheme.
