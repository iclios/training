5.2a · Composants & orchestration

Architecture d’une plateforme de paiement

Définition monétique

Qu’est-ce qu’une plateforme de paiement digitale ?

Ensemble de cinq composants cœurs qui orchestrent l’acceptation multi-canaux : Payment Gateway, Wallet Manager, Tokenization (TSP), Fraud Engine, Reconciliation & Settlement — autour d’une intention métier, d’un payment_id et d’un cycle Auth formel.

Schéma cible à quatre niveaux ; séquence d’échanges sur le chemin critique Auth ; puis workflows par canal.

Composants cœurs

Cinq briques fonctionnelles

Chaque composant a une responsabilité SI claire. Le Wallet Manager est hors chemin critique de l’autorisation immédiate (enrolment / cycle de vie).

Gateway · Wallet · TSP · Fraud · Clôture

Cinq cœurs · une plateforme

Composant Rôle fonctionnel
Payment Gateway Point d’entrée façade API / POS ; normalisation des requêtes omnicanales ; attribution du payment_id selon l’intention ; orchestration des appels.
Wallet Manager Enrôlement et cycle de vie des cartes enrôlées (provisioning, suspend, delete) — hors chemin critique de l’autorisation immédiate.
Tokenization Service (TSP) Conversion PAN → Token (EMVCo / MDES / VTS) et détokenisation pour le réseau / l’émetteur.
Fraud Engine Évaluation dynamique du risque contextuel (scoring en ligne, règles de vélocité) avant / autour de l’AuthZ.
Reconciliation & Settlement Clôture financière automatisée : rapprochement AuthZ / Clearing / Règlement sur le journal unique (1 vérité SI).

Vue d’ensemble

Schéma d’architecture cible

Quatre niveaux de haut en bas : canaux → Gateway & cœur SI → rails externes → clôture. Séquence critique : Gateway → TSP/QR → Fraud → Issuer AuthZ → écriture journal.

Quatre niveaux · séquence ①→⑤

Canaux · Cœur SI · Rails · Clôture

Wallet Manager = enrolment / cycle de vie — flèche en pointillés, pas sur le chemin ①–⑤ de l’Auth immédiate.

Repère : quatre niveaux empilés ; la séquence ①→⑤ est le chemin critique Auth ; la clôture lit le même journal que l’AuthZ.

Cas · canaux

Comment chaque canal traverse la plateforme

Chaque cas = une porte vers la même plateforme (gateway · fraude · journal). Deux achats distincts = deux payment_id ; un seul id seulement si c’est la même intention (même panier / ordre).

Porte → gateway → AuthZ → vérité SI

Même cycle formel · quel que soit le canal

Les 5 briques (Gateway, Wallet Manager, TSP, Fraud, Reconciliation) = responsabilités SI dans la chaîne omnicanale. Elles peuvent être réparties entre acteurs — ce n’est pas un seul acteur qui assure tous les modules.

Module Souvent chez…
Payment Gateway PSP / plateforme d’acceptation / switch
Wallet Manager OEM wallet + banque (enrolment) — hors Auth
TSP Scheme / réseau (VTS, MDES…)
Fraud Engine PSP, acquéreur, ou service dédié
Reconciliation & Settlement Plateforme + rails acquéreur / scheme / banques
AuthZ (hors « cœur » plateforme) Émetteur — décide, ne « vit » pas dans le gateway

Repère : les canaux = portes d’entrée ; les modules = fonctions de la chaîne ; les acteurs les opèrent de façon répartie.

Cas · 1 · Porte in-store

Workflow · in-store

Porte magasin (tap) : même plateforme que le web — pas forcément le même achat. Un tap « au hasard » = nouvel id ; un click & collect = reprise du panier existant.

Use case A : achat spontané en caisse. Use case B : retrait d’un panier web (même ordre).

Rappel · omnicanal

Quatre portes · une plateforme

Omnicanal = une plateforme pour toutes les portes — pas « un seul paiement pour tout le monde ». Continuité d’id = cas particulier (même intention / même ordre).

Ex. : deux achats distincts (web + magasin) = 2 payment_id sur le même journal ; click & collect = 1 id repris sur 2 portes.

Architecture fléchée · convergence omnicanale

4 entrées → 1 cœur → 1 journal SI · id par paiement

Signal omnicanal Ce qu’on vérifie
Plateforme unique 4 portes · 1 gateway · 1 journal SI
1 payment_id / paiement Deux intentions = deux ids · même SI
Continuité (option) Même ordre repris sur une autre porte
≠ Multicanal Pas 4 stacks / 4 journaux juxtaposés

Repère : 4 silos = multicanal ; 1 SI pour 4 portes = omnicanal ; 1 id partagé = seulement si même intention.
