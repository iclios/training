3.3

Architecture SI tokenisation

Idée clé — tableau

Merchant ou wallet, TSP, tokenization réseau et issuing system forment la chaîne SI minimale de la tokenisation. Le token naît dans cette chaîne, puis rejoint le flux d’autorisation.

Définition

Que montre l’architecture SI de tokenisation ?

Elle montre où se créent, se gouvernent et se réutilisent les tokens dans le système d’information. Le sujet n’est plus seulement “quel numéro circule”, mais quelles briques contrôlent son émission, son état et sa présentation au paiement.

Composants

Chaîne SI minimale

Du contexte d’usage au flux d’autorisation

Merchant / wallet · TSP · tokenization réseau · issuer

Rôles

Qui fait quoi dans la chaîne

  • Merchant / wallet — porte le besoin métier d’utiliser un moyen de paiement dans un canal ou un device
  • TSP — émet, active, suspend et gouverne le token
  • Network tokenization — ancre le token dans un domaine réseau / usage et facilite son exploitation
  • Issuing system — reste la référence carte, le lien produit / porteur et le point de décision d’autorisation

Distinction

TSP ≠ issuer

TSP

  • Gouvernance du token
  • Cycle de vie token
  • Contexte d’usage / device / domaine

Issuer

  • Carte source / compte / produit
  • Risque, opposition, plafonds
  • Décision finale d’autorisation

Piège fréquent

Dire “le token remplace l’émetteur” est faux. Il remplace un identifiant exposé dans le flux, pas la logique d’émission ni la décision de paiement.

Flux

Demande → gouvernance → présentation

  • Demande de token depuis un canal marchand ou wallet
  • Création / stockage / gouvernance du token
  • Rattachement à un domaine d’usage
  • Présentation du token dans le flux d’autorisation à la place du PAN

Ancrage

Cas pratiques

Cas 1 — Wallet mobile

  • Le wallet porte la demande d’usage
  • Le TSP gouverne le token
  • L’issuer reste la racine carte et la décision finale

Cas 2 — Merchant tokenisé

  • Le marchand conserve un identifiant substitutif
  • La gouvernance réelle est hors de son SI direct

Question salle

À quel endroit de cette chaîne votre banque garde-t-elle la maîtrise directe, et à quel endroit dépend-elle d’un scheme, d’un TSP ou d’un wallet provider ?

Notes formateur — points à faire verbaliser
  • Le token naît dans une architecture de gouvernance, puis entre dans le paiement
  • Merchant, wallet, TSP et issuer n’ont pas le même rôle ni le même niveau de responsabilité
  • Ce bloc prépare directement la compréhension des wallets et du NFC mobile

Check de fin de bloc

  • Chaîne SI décrite de bout en bout
  • TSP vs issuer correctement distingués
  • Le point d’entrée du token dans l’autorisation est compris
  • Le pont vers J4 est explicite
