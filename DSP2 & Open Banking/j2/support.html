Authentification

OAuth2, OIDC, mTLS, JWT

  • RFC 6749 (OAuth2) — le socle des autorisations ; authorization_code, refresh_token, scope, PKCE.
  • RFC 7636 (PKCE) — protection du flux code contre l’interception ; recommandé, souvent obligatoire en Open Banking.
  • OpenID Connect Core 1.0 — identité au-dessus d’OAuth2 (id_token), pour authentifier Lyam.
  • RFC 7519 (JWT) — format du jeton portant les scope, l’émetteur, l’audience et l’expiration.
  • RFC 8705 (mTLS / OAuth 2.0 mTLS) — authentification mutuelle par certificat, exigée pour identifier le TPP.
  • eIDAS & QWAC — cadre des certificats qualifiés utilisés pour le mTLS en Europe.

Sécurité & conformité

SCA, RTS et référentiels

Textes DSP2

DSP2 art. 97 (SCA) et art. 98 (RTS) ; RTS (UE) 2018/389 sur l’authentification forte et la communication sécurisée. À lire avec les Q&A EBA sur les exemptions.

Référentiels sécurité

OWASP API Security Top 10 — BOLA, broken auth, excessive data exposure : la grille de lecture des risques API. Et le RGPD pour les données personnelles.

À lire en priorité

Pour un architecte débutant sur le sujet : le résumé du flux OAuth2 (RFC 6749 §4.1) + PKCE (RFC 7636), puis la documentation NextGenPSD2 sur les consentements, puis l’OWASP API Security Top 10. Cela couvre l’essentiel du Jour 2.
