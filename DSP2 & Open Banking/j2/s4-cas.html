Cas pratique

Banque Est doit ouvrir une API à un TPP de bout en bout. À vous de produire le schéma d’architecture, le flux OAuth et les points de contrôle de sécurité.

Fil rouge

L’application de Lyam (« FinanceApp ») demande à Banque Est un accès en lecture à ses deux comptes. Vous êtes l’équipe technique de Banque Est : il faut le brancher proprement — et en sécurité.

Énoncé

Le cas

FinanceApp est un AISP agréé. Banque Est doit lui ouvrir un accès en lecture aux comptes d’un client qui l’a autorisé, via une API Open Banking, en respectant les exigences du Jour 2.

Consigne

Ce qu’il faut produire

  1. Schéma d’architecture — placer les composants entre FinanceApp et le core bancaire (Gateway, API Management, services AIS, consentement, logs).
  2. Flux d’authentification — décrire les étapes OAuth2 : demande, redirection, SCA de Lyam, consentement, code, échange contre jeton, appel API.
  3. Points de contrôle sécurité — pour chaque étape, indiquer le contrôle appliqué (mTLS, vérification registre, scopes, throttling, anti-rejeu) et ce qui est journalisé.
  4. Trois risques et une mesure chacun — usurpation, attaque API, fuite de données.

Livrable attendu

Une page par groupe : schéma + flux + tableau des points de contrôle + risques/mesures. Restitution 5 min par groupe, synthèse 10 min.

Corrigé formateur
  • Schéma — FinanceApp → [mTLS] → Gateway → API Management → Service AIS → [vérif consentement] → core. Logs en parallèle sur toute la chaîne.
  • Flux — code d’autorisation (avec redirection), SCA chez la banque, consentement affiché, code échangé contre access token (JWT portant le scope AIS), Bearer pour chaque appel.
  • Piège à faire dire : la SCA valide la personne, le mTLS le TPP, le scope l’autorisation. Confondre les trois = erreur fréquente.
  • Exemptions : ne pas laisser un groupe appliquer « consentement 90 jours » à un PIS : le cas ne porte que sur l’AIS, mais la confusion revient vite.

Bilan du Jour 2

  • Les trois types d’API et leurs composants sont maîtrisés.
  • OAuth2, OIDC, mTLS et JWT sont distingués.
  • SCA, exemptions et preuve sont comprises.
  • Je sais relier chaque risque à une mesure.
  • Je sais concevoir l’ouverture sécurisée d’une API à un TPP.
