Ce jeton remplace l’identifiant + mot de passe. Il est limité aux comptes choisis, daté, et révocable.

MonBuddy · application tierce

MonBuddy n’a jamais le mot de passe de Lyam. Elle ne reçoit qu’un jeton, porteur de droits limités.

À observer. Comparez avec le labo scraping : là-bas, MonBuddy stockait le mot de passe « en clair ». Ici, sans mot de passe, une fuite du jeton n’expose que les comptes autorisés, et pour la durée choisie.

MonBuddy · données reçues

Aucun parsing de balises : MonBuddy lit directement des champs nommés. Une refonte du site web ne casse rien ici.

Aucun compte pour l’instant. Cliquez sur « Appeler /accounts ».
Stable par contrat. L’API est versionnée (/v1) : les champs ne changent pas dans ton dos, contrairement aux classes CSS d’une page.

Après révocation, MonBuddy réessaie d’appeler l’API avec son ancien jeton. La banque doit refuser.

Révoquez le consentement à gauche, puis réessayez.

Ce que vous venez de voir. La révocation coupe l’accès tout de suite, sans que Lyam ait à changer son mot de passe. Avec le scraping, il n’y avait aucun bouton « révoquer » : il fallait changer le mot de passe — ce qui ne bloquait même pas MonBuddy, qui l’avait stocké. C’est la limite que la DSP2 corrige.
